# Aot: морфологический анализ русского языка на Java

[English version](README.md)

Aot — словарный морфологический анализатор русского языка. Библиотека находит
леммы, морфологические признаки и формы слова, возвращая несколько вариантов
разбора при неоднозначности. Выбрать подходящий вариант по контексту предложения
должно приложение.

Проект перерабатывает [aot-lematizer](https://github.com/bazhenov/aot-lematizer):
упрощает API и сборку, устраняет зависимости с закрытым исходным кодом.

## Подключение

Добавьте репозиторий [JitPack](https://jitpack.io/#demidko/aot) и выберите опубликованную
версию. Пример для Gradle Kotlin DSL:

```kotlin
repositories {
    mavenCentral()
    maven("https://jitpack.io")
}
dependencies {
    implementation("com.github.demidko:aot:2025.11.25")
}
```

Исходный код использует возможности языка, совместимые с Java 8. Для сборки
нужен JDK, поддерживаемый Gradle Wrapper этого проекта; тесты и измерения
производительности выполнены на JDK 21. Требования опубликованного JitPack-артефакта
к версии Java также зависят от JDK, использованного при его сборке.

## Использование

```java
import com.github.demidko.aot.WordformMeaning;
import java.util.List;

class Example {
    public static void main(String[] args) {
        List<WordformMeaning> meanings = WordformMeaning.lookupForMeanings("люди");
        for (WordformMeaning meaning : meanings) {
            System.out.println(meaning.getLemma());      // человек
            System.out.println(meaning.getMorphology()); // словарные теги
            System.out.println(meaning.getPartOfSpeech());
            for (WordformMeaning form : meaning.getTransformations()) {
                System.out.println(form + " " + form.getMorphology());
            }
        }
    }
}
```

`getTransformations()` возвращает всю словарную парадигму. Для склонения или спряжения
выберите из неё формы с нужными морфологическими признаками; отдельного метода
изменения формы нет. Лемма — словарная начальная форма, например инфинитив глагола,
а не обязательно форма первого лица единственного числа.

Для `замок` в поставляемом словаре есть пять разборов. Разные разборы могут иметь
одинаковые написание и теги. Если приложению важна неоднозначность, сохраняйте
идентичность разборов и повторения. Библиотека не возвращает толкования, позволяющие
различить замок-строение и замок-запор.

## Входные данные и идентификаторы

- Поиск переводит строку в нижний регистр с учётом локали JVM и заменяет `ё` на `е`.
- Передавайте отдельное слово. Поиск не удаляет пробелы и ударения, не разбивает
  текст на слова и не нормализует комбинируемые символы Unicode. Для неизвестного
  слова возвращается пустой список, для `null` выбрасывается `NullPointerException`.
- `getId()` и `lookupForMeaning(long)` позволяют восстановить разбор. Идентификатор
  содержит индексы словаря и стабилен только при том же порядке его записей.
  Сохраняйте версию словаря вместе с ID. Корректность ID не проверяется: многие
  неверные индексы вызывают исключение при обращении, но крайние значения индекса
  формы могут из-за переполнения указывать на допустимую форму.
- Порядок разборов и повторения отражают словарь, а не оценку вероятности.
- Не изменяйте списки из `listAllFlexions()` и `getMorphology()`: это изменяемые
  списки фиксированного размера, связанные с общими массивами словаря.

Словарь загружается при первом обращении и остаётся в памяти. Учитывайте задержку
инициализации и расход памяти при развёртывании.

## Словарь и происхождение данных

Слова и морфология взяты из [morph_dict](https://github.com/sokirko74/morph_dict).
[aot-compiler](https://github.com/demidko/aot-compiler) преобразует исторические
MRD/TAB-файлы в поставляемый `mrd.gz`, а [aot-bytecode](https://github.com/demidko/aot-bytecode)
задаёт общие теги и кодировку. Описание исторического формата находится в
[Morph_UNIX.txt проекта AOT](https://github.com/sokirko74/aot/blob/master/Docs/Morph_UNIX.txt).
Текущая структура upstream-репозитория может отличаться от этих исходных файлов.

Бинарный словарь обновлён 24 ноября 2025 года с исправлениями от @danil-kondr2016.
Эта дата не гарантирует актуальность словарного состава. Точные коммиты, контрольные
суммы, наблюдаемое поведение и ограничения происхождения перечислены в
[описании базовой версии](docs/characterization.md). Java-проект распространяется
по [лицензии MIT](LICENSE); условия использования словарных данных следует уточнять
по первоисточникам, а не выводить из лицензии программного кода.

## Разработка

```sh
bash gradlew test
```

[Набор проверок](docs/characterization.md) отделяет наблюдаемое поведение от
лингвистической правильности. [Измерения производительности](docs/benchmarks.md)
охватывают поиск после прогрева, работу с ID, выделение памяти и первое обращение.
